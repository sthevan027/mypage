O PR Indicator já vivia em dois lugares: a barra do GNOME, como extensão, e a bandeja do Windows, como app Electron. Faltava o resto do Linux. No KDE, no XFCE e em qualquer desktop que não seja GNOME, a extensão simplesmente não roda.

A versão **1.1.0** fecha essa lacuna. O código da pasta `windows/` agora também roda no Linux, com o mesmo popup, os mesmos temas e a mesma configuração. Mudou o que o sistema permite fazer, e isso deu mais trabalho do que eu imaginei.

## O mesmo código, outra bandeja

A bandeja do Linux usa o padrão StatusNotifier, que é o que o KDE Plasma já usa. O app não precisou de um código novo para cada desktop: ele fala com a bandeja pelo padrão e o resto é igual ao Windows.

Vale deixar claro: se você está no GNOME, a extensão continua sendo a melhor opção. A versão de bandeja é pra quem está fora dele.

## Sem hover, o número vai pro ícone

No Windows, o número de PRs aparece quando o mouse passa por cima do ícone. No Linux, a bandeja não avisa quando o mouse entra no ícone. Então o logo do GitHub leva o número num selo, sempre visível. O tooltip também mostra a contagem.

Os cliques ficaram assim:

- **clique esquerdo** abre o popup;
- **clique direito** abre um menu com *Abrir*, *Atualizar agora* e *Sair*.

Foi a primeira lição de verdade: uma coisa que era só visual no Windows virou informação obrigatória no Linux.

## Wayland: quem decide a posição é o compositor

Esse foi o trecho mais chato. No X11, o app abre o popup num canto da tela principal, escolhido por `PR_INDICATOR_CORNER` (superior direito por padrão). No Wayland, o app não escolhe onde a janela aparece. Sem ajuda, o compositor coloca a janela no meio da tela.

Pra resolver no KDE, escrevi um script para o KWin que fixa o popup no canto superior direito, abaixo do painel:

```bash
./linux/install-kwin-position.sh            # instala e ativa
./linux/install-kwin-position.sh --remove   # desativa e remove
```

Ele só mexe na janela do PR Indicator. Outro detalhe: no Wayland, o popup não aparecia pelo XWayland. Então, quando a sessão é Wayland, o app usa Wayland nativo. Se precisar forçar, `PR_INDICATOR_OZONE=x11` ou `wayland` sobrepõe a escolha.

## Autostart e token

O autostart grava `~/.config/autostart/pr-indicator.desktop`. No AppImage, ele liga sozinho na primeira execução, igual ao `.exe` instalado no Windows.

O token manual é cifrado pelo cofre do sistema, KWallet ou libsecret, via `safeStorage`. Se o sistema não tiver cofre, a recomendação é usar o `gh` CLI, que já guarda o login.

## O que os testes pegam e o que não pegam

Entraram testes para a escolha do canto e para o arquivo de autostart. Isso pega a conta errada e o arquivo mal gravado. O que não pega é o popup aparecendo no lugar certo numa tela de verdade. Essa parte ainda depende de alguém olhar o painel.

## O que eu levo disso

- **Cada desktop tem uma bandeja diferente.** O código de lógica é o mesmo; o que muda é o adaptador de cada sistema.
- **Quando o sistema não deixa, a solução vira script do sistema.** No Wayland, o app não controla a posição da janela. O KWin controla, então o ajuste foi feito lá.
- **Recurso visual precisa de plano B.** Sem hover, o número foi pro ícone.

O AppImage e o código estão no [repositório](https://github.com/sthevan027/gnome-pr-indicator), e a versão está na [release v1.1.0](https://github.com/sthevan027/gnome-pr-indicator/releases/tag/v1.1.0).
